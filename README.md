# KOBI 75

כלי מעקב אישי לאתגר 75 ימים. קובץ HTML יחיד (`index.html`), ללא שרת, ללא תלויות חיצוניות, עובד לגמרי אופליין. כל הנתונים נשמרים מקומית בדפדפן (`localStorage`).

## איך פותחים את האפליקציה

**אופציה א' - קובץ מקומי:**
פתיחת `index.html` ישירות בדפדפן בנייד (למשל שליחה עצמית של הקובץ ופתיחה ב-Safari/Chrome). עובד באופן מלא, כולל אופליין, אבל בלי אפשרות "התקנה" אמיתית למסך הבית ובלי Service Worker (זה דורש כתובת מאובטחת - ראו למטה).

**אופציה ב' - GitHub Pages (מומלץ):**
1. בהגדרות הריפו: Settings → Pages → Deploy from a branch → לבחור את הענף הרלוונטי ותיקיית `/ (root)`.
2. אחרי כמה דקות תופיע כתובת מהצורה `https://<user>.github.io/kobi75/`. לפתוח אותה בנייד.
3. ב-Safari: כפתור שיתוף → **הוספה למסך הבית**. כך נוצר אייקון שנפתח כאפליקציה מסך-מלא, כולל תמיכת אופליין אמיתית דרך `sw.js`.

## גיבוי ושחזור נתונים

הנתונים נשמרים ב-`localStorage`, שעלול להימחק על ידי המערכת (בעיקר ב-iOS) אחרי תקופה של אי-שימוש בדפדפן. **חשוב לגבות באופן קבוע.**

**גיבוי:** מסך הגדרות → **ייצוא JSON**. הכפתור גם מעתיק את הנתונים ללוח וגם מוריד קובץ `kobi75-backup-<תאריך>.json`. האפליקציה מציגה באנר תזכורת בראש מסך היום אם עברו 7 ימים או יותר מהגיבוי האחרון.

**שחזור:** מסך הגדרות → הדבקת תוכן קובץ הגיבוי (JSON) בתיבת **ייבוא JSON** → לחיצה על ייבוא. פעולה זו מחליפה את כל הנתונים הקיימים בנתונים מהקובץ.

**איפוס מלא:** מסך הגדרות → **איפוס מלא**, מוחק את כל הנתונים לצמיתות. דורש אישור כפול.

## עדכון קוד - חובה: העלאת גרסת המטמון ב-sw.js

כשמתקינים את האפליקציה למסך הבית מ-`https`, קובץ `sw.js` שומר עותק של `index.html` במטמון כדי שהאפליקציה תיפתח מהר ותעבוד אופליין בלי תלות ברשת.

המשמעות: **כל שינוי בקוד (`index.html`) חייב להיות מלווה בהעלאת המספר בקבוע `CACHE_NAME` בראש `sw.js`** (למשל `kobi75-cache-v1` → `kobi75-cache-v2`).

- אם לא מעלים את המספר - מכשירים שכבר התקינו את האפליקציה ימשיכו לקבל את הגרסה הישנה מהמטמון, גם אחרי רענון ידני.
- אחרי העלאת המספר, ה-Service Worker מזהה גרסת מטמון חדשה, מוריד את הקובץ המעודכן, ומוחק את המטמון הישן באירוע ה-`activate` הבא.
- שינוי לוקח אפקט בפתיחה הבאה של האפליקציה (לפעמים נדרשת סגירה מלאה ופתיחה מחדש, לא רק רענון, בהתאם לדפדפן).

בפיתוח מקומי (`file://`) אין Service Worker בכלל, כך ששינויים נראים מיד בכל רענון - אין צורך לעדכן גרסה כשעובדים ככה.
